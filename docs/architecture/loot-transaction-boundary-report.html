LootTransactionService 서버 도메인 경계 구현 보고서

이 문서는 FishNet Game Server 안에서 먼저 동작하는 루팅 스모크 구현을 DB/Backend로 옮기기 쉬운 순수 도메인 transaction 경계와 FishNet 어댑터 경계로 나눈 결과를 사람이 빠르게 이해할 수 있게 정리한 보고서다.

작성일: 2026-05-27 범위: Loot transaction boundary 커밋: 하지 않음 검증: .omx evaluator 대상

1. 핵심 변경 요약

순수 도메인 경계 추가

LootTransactionService가 requestId 멱등성, 아이템 상태 전이, 소유권 확정을 담당한다.

임시 저장소 추가

InMemoryItemInstanceRepository는 현재 FishNet 서버 안에서만 쓰는 v0 저장소이며, 나중에 DB repository로 교체하기 쉽게 분리했다.

FishNet 어댑터 얇게 정리

GamePlayer.LootServer는 Scene 탐색, 거리 검증, NetworkObject projection 갱신만 담당하고 판정은 도메인에 위임한다.

회귀 테스트 추가

LootTransactionServiceTests로 성공, 중복 요청, 이미 획득된 아이템, 미발견, 거리 실패, invalid request를 고정했다.

Mermaid가 차단된 환경에서는 아래 코드 블록 자체가 설계 원문이다.

classDiagram
    class GamePlayer_LootServer {
      +ServerRequestLoot(requestIdValue, itemIdValue)

    }

    class LootItem {

      +State

      -InMemoryItemInstanceRepository repository

    class InMemoryItemInstanceRepository {
      -Dictionary~LootItemIdentity, ItemInstanceRecord~ records

    class LootCommand {

    class LootDecision {

5. 객체별 간단 설명

객체현재 책임아닌 것
GamePlayer.LootServer FishNet ServerRpc 진입점, Unity Scene 탐색, 거리 검증, NetworkObject 상태 반영 아이템 소유권 규칙의 최종 판정자 아님
LootItem 월드에 보이는 전리품 projection. ObserversRpc로 클라이언트 표시를 갱신 DB entity 또는 전체 아이템 모델 아님
LootTransactionService requestId 멱등성, item state 확인, owner commit/reject 판정 FishNet, Unity Transform, UI, 입력 처리 담당 아님
InMemoryItemInstanceRepository 스모크 단계에서 transaction 상태를 메모리에 보관 영구 저장소 아님. 서버 재시작 후 유지 보장 없음
ItemInstanceRecord 도메인 transaction이 보는 최소 아이템 인스턴스 상태 장비 옵션, 수량 stack, durability 등 전체 인벤토리 모델 아님
LootCommand 어댑터가 검증한 요청 입력 묶음 클라이언트 신뢰 데이터 아님. 서버에서 만든 command
LootDecision transaction 결과를 FishNet adapter에 돌려주는 값 직접 네트워크 전송 DTO로 고정된 계약은 아님

6. 현재 범위와 남은 결정

  • 완료: 루팅 단일 아이템 획득의 서버 권한 commit/reject/duplicate 판정 경계를 만들었다.
  • 완료: FishNet ServerRpc 쪽은 도메인 판정 결과만 받아 월드 projection을 갱신하도록 정리했다.
  • 아직 아님: 실제 DB, backend server, stackable inventory, 거래/드랍/분할 stack 로직은 구현 범위에 포함하지 않았다.
  • 아직 아님: ItemInstanceRecord는 v0 최소 모델이다. 포션 16개 stack처럼 수량/slot/instance 정책은 다음 인벤토리 도메인 설계에서 확장해야 한다.

7. 검증 기준

  • 순수 도메인 파일이 UnityEngine, FishNet을 참조하지 않는다.
  • GamePlayer.LootServer가 LootTransactionService, LootCommand, LootDecision를 통해 도메인 경계를 사용한다.
  • standalone C# harness가 성공/중복/이미 획득/미발견/scene projection 누락/거리 실패/invalid request를 통과한다.
  • 이 HTML 문서가 클래스 다이어그램, 관계도, 객체 설명을 포함한다.
