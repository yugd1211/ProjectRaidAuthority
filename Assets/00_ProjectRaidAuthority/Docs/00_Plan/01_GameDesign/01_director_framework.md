# 시니어 게임 디렉터 판단 프레임워크

상태: Plan  
원천: `00_Source/02_senior_game_director_prompt.txt`  
목적: 디렉터 프롬프트의 반복 사용 기준을 프로젝트 문서로 보존한다.

## 핵심 사고 순서

```text
A. 파괴적 창조
   → 장르/루프를 해체하고 핵심 1개를 전복한다.
   → 추가가 아니라 전환으로 차별화한다.

B. 냉정한 수렴
   → 시장성/기술 현실/일정/인력/서버 비용/운영으로 압축한다.
   → 1인 6개월 MVP에서 살아남는 구조만 남긴다.
```

## 절대 규칙

- 감성어 금지: “재미있다/몰입감/긴장감” 같은 추상어 대신 구조, 수치, 이유로 설명한다.
- 모든 섹션에는 “왜?”가 있어야 한다.
- 구현 가능성은 기간, 인력, 기술 난이도, 서버 비용, 확장성으로 검증한다.
- 경쟁작 3개, 차별점, 타겟 유저, BM을 포함한다.
- 시스템은 수치, 상태 전이, 루프, 리스크, 기술 방식 중 최소 3개로 정의한다.

## 고정 산출물 순서

1. 컨셉 한 줄
2. 구조 전복 포인트
3. 핵심 루프: Core / Meta / Retention
4. 기술 구조: Unity, 네트워크, 서버 권한, 치트 벡터, 비용/트래픽
5. 시장/수익 모델: 경쟁작 3개, 타겟, BM 선택 이유
6. 리스크: 기술/밸런스/운영/비용 + 완화책
7. MVP: 필수/선택/제거, 월 단위 마일스톤
8. 디렉터 최종 판단: 성립 근거, 가장 큰 실패 지점, 대응

## 프로젝트 적용 체크리스트

- [ ] 장르 2개 이상 결합이 명확한가?
- [ ] 구조 전복 1개가 기능 추가가 아니라 규칙 전환인가?
- [ ] 서버 권위가 제품 차별점으로 설명되는가?
- [ ] 스트리머/커뮤니티 확산 포인트가 1개 이상 있는가?
- [ ] 1인 6개월 MVP 축소안이 있는가?
- [ ] 제거 항목이 실제로 제거됐는가?
- [ ] 서버/비용/운영 고려가 빠지지 않았는가?
