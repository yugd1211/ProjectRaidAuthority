# 6개월 MVP 프로덕트 플랜 초안

상태: Plan  
원천: `00_Source/00_pm_development_plan.md`  
목적: PM 개발 계획에서 일정/우선순위/게이트만 분리한다.

## 우선순위 원칙

| 기준 | 설명 | 적용 |
|---|---|---|
| 의존성 | 뒤 기능이 앞 기능에 기대는가 | 특성 시스템은 전투/상태/저장 이후 |
| 리스크 제거 | 실패 시 전체 일정이 무너지는가 | 서버 판정, 인벤토리 중복, 레이드 저장 |
| 포트폴리오 가치 | 차별점을 증명하는가 | 서버 권위, 치트 대응, Docker 운영 |
| 콘텐츠 증폭력 | 적은 구현으로 변주를 만드는가 | 특성/시너지/저주 |

## 개발 순서 고정안

```text
1. 서버 권위 뼈대
2. 전투 판정
3. 인벤토리/저장 무결성
4. 한 판 완주 가능한 레이드 플로우
5. 특성/시너지/저주
6. 운영/배포/최적화
```

## 월별 로드맵

| 월 | 목표 | 핵심 산출물 | 종료 기준 |
|---:|---|---|---|
| 1개월차 | 정의 + 서버 코어 | PRD, 서버 Tick, Entity 구조, 접속 테스트 | 클라이언트가 서버에 접속하고 더미 엔티티 동기화 |
| 2개월차 | 전투 코어 | 이동, 발사, 서버 히트 판정, 기본 AI | 서버 기준 전투 성립 |
| 3개월차 | 인벤토리 + 레이드 플로우 | 루팅, 소유권, 탈출, 결과 저장 | 한 판 완주 가능 |
| 4개월차 | 로그라이크 레이어 | 특성 8개, 시너지 4개, 저주 3개 | 런마다 선택 변화 발생 |
| 5개월차 | 리텐션 + 운영 초안 | 메타 해금, 고위험 탈출, 이벤트 로그, Docker | 반복 플레이 구조와 운영 구조 확인 |
| 6개월차 | 안정화 + 포트폴리오 | QA, 최적화, 데모 빌드, 발표 문서 | 외부 시연 가능한 MVP |

## Phase Gate

| Phase | 통과 조건 |
|---|---|
| Phase 0 정의 | 서버가 확정할 항목, MVP 제외 항목, Core Loop가 문서화됨 |
| Phase 1 서버 코어 | 클라 1~2개 접속, 서버 기준 위치 동기화, 더미 엔티티 Tick 처리 |
| Phase 2 전투/AI | 서버 기준 HP 감소, 상태이상 Tick, AI 탐지/추적/공격 |
| Phase 3 인벤토리 | 동시 루팅 중복 0건, requestId 멱등 처리, 성공 탈출만 저장 |
| Phase 4 레이드 | 입장→전투→루팅→탈출→저장 1회 완주 |
| Phase 5 로그라이크 | 3지선다, 8개 특성, 4개 시너지, 3개 저주 적용 |
| Phase 6 운영 | Docker 멀티 인스턴스, 이벤트 로그, QA 리포트 |

## 매주 확인 질문

- 서버 권위가 깨진 기능이 있는가?
- 클라이언트가 결과를 직접 확정하는 코드가 있는가?
- 루팅/저장 요청은 멱등 처리되는가?
- 새 기능이 스냅샷 크기나 서버 부하를 급증시키는가?
- 이번 주 기능이 MVP 필수 항목인가?
