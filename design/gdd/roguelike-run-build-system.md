# Roguelike Run Build

> **상태**: 아키텍처 계획 기준 승인  
> **작성 기준일**: 2026-05-13  
> **구현 축**: 위험한 즉흥 빌드 선택  
> **주의**: 실제 수치는 Unity/FishNet smoke prototype 측정 전까지 후보값이다.

## 개요

raid 중 특성, 시너지, 저주, 임시 강화 선택을 서버 권한으로 관리해 반복 플레이 변주를 만든다.

## 플레이어 판타지

플레이어는 “망한 선택 같지만 강해질 수 있다”는 우스꽝스럽고 위험한 빌드 감각을 느껴야 한다.

## 상세 규칙

1. 특성 선택 후보는 서버가 생성한다.
2. 선택 확정은 서버 validation 후 적용된다.
3. 특성은 전투/전리품/추출 수치에 명시적으로 연결된다.
4. 저주나 부작용은 수치와 UI 설명을 함께 가진다.
5. MVP는 적은 수의 강한 변주를 우선한다.

## 수식

```text
modified_value = base_value * (1 + additive_bonus) * multiplicative_bonus
risk_score = benefit_score - curse_cost
```

수식은 구현 전 검증용 기준이다. 최종 타입과 직렬화 방식은 Unity/FishNet API 확인 후 결정한다.

## 예외 상황

- 동일 선택 요청이 중복 도착하면 한 번만 적용한다.
- 선택 시간이 끝나면 서버 기본 정책을 적용한다.
- 서로 충돌하는 특성은 우선순위나 금지 조합으로 해결한다.

## 의존성

- 서버 권한 핵심
- 전투와 AI
- 인벤토리와 전리품
- HUD/결과 화면

## 조정값

- offer_count
- rarity_weights
- curse_chance
- synergy_threshold

## 수용 기준

- [ ] 특성 후보와 선택 결과가 서버 로그에 남는다.
- [ ] 클라이언트가 임의 특성을 적용할 수 없다.
- [ ] 특성 효과가 최소 하나의 전투/loot 수치에 반영된다.
- [ ] 결과 화면에 선택한 특성이 표시된다.
